## 模型配置

使用 `requirements-live.lock` 安装锁定的依赖。`providers.make_model()` 返回 LangChain `BaseChatModel`，业务层通过模型接口调用。自定义端点使用 `BaseChatOpenAI` 保留兼容接口的 `max_tokens` 参数，默认 OpenAI 端点使用 `ChatOpenAI`。SDK 的 HTTP 代理遵循环境配置。

| 环境变量 | 用途 |
| --- | --- |
| `MODEL_PROVIDER` | 默认 `fake`；真实服务填 `openai` |
| `MODEL_NAME` | 实际模型 ID，本次使用 `deepseek-flash` |
| `OPENAI_BASE_URL` | 兼容端点的 HTTPS 地址；DeepSeek 地址 `https://api.deepseek.com` |
| `OPENAI_API_KEY` | 进程读取的 Key；Actions 从 `DEEPSEEK_API_KEY` Secret 注入 |
| `MODEL_THINKING` | 可选 `enabled` / `disabled`；用于支持 `thinking` 参数的兼容服务 |
| `MODEL_INPUT_USD_PER_MILLION` | 已确认的每百万输入 Token 美元价格 |
| `MODEL_OUTPUT_USD_PER_MILLION` | 已确认的每百万输出 Token 美元价格 |

已于 2026-10-12 核对 [DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)及[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)文档。配置使用官方推荐名称 `deepseek-flash`（V4.1 Flash），使用高峰、缓存未命中的输入 $0.30、输出 $1.20／百万 Token，并设置 `MODEL_THINKING=disabled` 以配合短输出预算。价格只是显式示例配置，业务代码仍要求有限非负价格；缺少任一价格时 live 模式拒绝启动。账户可用性和真实质量仍待调用验证。若模型区分缓存命中与未命中，预算输入价使用适用的较高价格；报告为该配置下的费用估算，实际账单可能因缓存或服务层级而不同。

使用下面的 GitHub Actions 路径时，由 GitHub 托管 runner 访问 DeepSeek。若在受限的 Codex 云环境中直接运行，则需另外允许 `api.deepseek.com` 并配置该环境自己的 Secret。

## GitHub Actions 实测（推荐）

工作流为 `.github/workflows/live-smoke.yml`，名称 **DeepSeek M1 smoke**。配置如下：

1. 在 GitHub 仓库 **Settings → Environments** 使用已创建的 `test-env`。
2. 在其 **Environment secrets** 中添加 `DEEPSEEK_API_KEY`，值为 TimeX 专用的 DeepSeek Key。
3. 工作流已配置公开价格默认值：输入 `0.30`、输出 `1.20` 美元／百万 Token，使用上文核对的高峰、缓存未命中价格。可选：在 **Environment variables** 中设置 `MODEL_INPUT_USD_PER_MILLION`、`MODEL_OUTPUT_USD_PER_MILLION` 覆盖默认值；执行前按当前价格更新。
4. 把 Environment 的可运行分支限制为仓库默认分支；账户套餐支持时，可增加 required reviewers。
5. 将工作流纳入默认分支后，在 **Actions → DeepSeek M1 smoke → Run workflow** 手动运行，选择默认分支，先用默认的 `check` 模式确认配置通过；准备好实测后再选择 `live`。
6. 在运行页面下载 `m1-deepseek-<run_id>-<run_attempt>` artifact，内含 JSON 与 Markdown，保留 7 天。

Key 仅在配置检查及模型调用步骤通过环境变量注入为 `OPENAI_API_KEY`；配置 YAML 只引用 Secret 名称。安装依赖、渲染报告和上传 artifact 的步骤不声明这个 Secret。模型名和价格放在普通配置或 Variables 中即可。

工作流只响应手动触发，并限制默认分支，固定使用仓库的合成样例。默认 `check` 模式检查 Secret 非空、价格配置有效，不请求模型 API；它不验证 Key 是否有效或账户余额。`live` 模式才会执行真实对照。PR / push 继续走 fake CI。成功或部分结果均可保存为 artifact；部分结果保留失败状态。Markdown 从同一份 JSON 渲染，避免为了两种格式再调用一次模型。模型费用预算为每份议会 / 单助手 $0.25，合计软预算 $0.50，另有 Actions 自身用量。工作流串行、总超时 15 分钟。

GitHub 在保存和传输 Secret 时提供保护；运行时，获授权的代码仍能读取 Key。因此只运行已审阅的默认分支代码，保持最小仓库写权限，并用专用 Key 便于撤销或轮换。避免打印环境变量或将 Key 写入 artifact，日志遮罩不能代替这些做法。

Environment 的可用性与保护规则受仓库可见性、GitHub 套餐影响。若当前私有仓库套餐不支持 Environment Secrets，可使用 **Settings → Secrets and variables → Actions** 的 repository secret，仍命名 `DEEPSEEK_API_KEY`；同时移除工作流中的 `environment: test-env`，保留默认分支限制与手动触发。公开价格可沿用工作流默认值，也可使用 repository variables 覆盖。

如果希望通过 CLI 管理 Environment variables，可在具备该仓库 `Environments: write` 权限的 GitHub 登录上下文中执行：

```bash
gh variable set MODEL_INPUT_USD_PER_MILLION --repo ratio-dd/timex --env test-env --body '0.30'
gh variable set MODEL_OUTPUT_USD_PER_MILLION --repo ratio-dd/timex --env test-env --body '1.20'
```

参考：[GitHub CLI variable set](https://cli.github.com/manual/gh_variable_set)、[Environment variable API 权限](https://docs.github.com/en/rest/actions/variables#create-an-environment-variable)。这两个值是公开配置，可以写入版本控制；API Key 始终通过 Secret 引用。

当前 POC 用 Actions Secrets 即可。后续长期运行服务再根据运行平台选择 Secret Manager；未来 AWS 部署身份使用 OIDC 短期凭证，DeepSeek 的 API Key 则仍按服务端密钥管理。OIDC 是否能替代模型 Key，取决于模型服务是否支持该身份方式。

参考：[GitHub Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)、[GitHub Environments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)。

## 普通 Python 环境执行


默认示例包含合成事实与用户约束。配置好 Secret 和网络后，载入已核对的示例配置再运行：

```bash
source examples/deepseek.env.example
python -m timex.cli --live --compare \
  --request examples/demo_request.json \
  --format json --output outputs/m1-live-comparison.json
```

程序先运行议会，再使用同一份请求和模型运行单助手。单助手同时考虑四项利益，但看不到议会输出。议会失败时跳过单助手，以停止追加请求。两种方案分别使用单次运行预算；通常合计 10 次调用，在双方各使用一次重试时最多 12 次。

把已保存的 JSON 渲染为 Markdown，可复用同一份实测而无需再调用模型：

```bash
python - <<'PY'
import json
from pathlib import Path
from timex.cli import comparison_markdown
report = json.loads(Path('outputs/m1-live-comparison.json').read_text(encoding='utf-8'))
with Path('outputs/m1-live-comparison.md').open('x', encoding='utf-8') as destination:
    destination.write(comparison_markdown(report))
PY
```

报告包含执行 ID、时间、输入摘要、约束、两轮观点、同伴引用、让步、分歧、单助手方案、每次尝试的状态、供应商返回的模型名与用量，以及合计费用估算和时延。人工评分保留为空，由用户按 POC 中的四项问题评价。一次案例仅提供观察，不预设多 Agent 优于单助手。

## 调用保护

| 配置项 | 默认值 |
| --- | ---: |
| `MAX_MODEL_CALLS` | 10，允许调低 |
| `MAX_RETRIES` | 1，整个运行共享，可设为 0 |
| `MAX_INPUT_TOKENS` | 16000，调用前估算及调用后检查 |
| `MAX_OUTPUT_TOKENS` | 1600，通过 API 参数限制 |
| `MAX_TOTAL_TOKENS` | 120000，单次运行的累计 Token 预算 |
| `MAX_INPUT_CHARACTERS` | 30000，包括系统规则、schema 与输入 |
| `MAX_OUTPUT_CHARACTERS` | 12000 |
| `CALL_TIMEOUT_SECONDS` | 60 |
| `TOTAL_TIMEOUT_SECONDS` | 300 |
| `MAX_ESTIMATED_USD_PER_RUN` | 0.25 |

单次运行指一份议会或一份单助手建议；对照默认合计费用软预算最多 $0.50。预算在发请求前检查，每次尝试都计数，包括格式错误、429 和 5xx。返回用量后用实际 Token 替换该次预留估算；若返回值已超过限制，立即停止后续调用。默认串行执行。

输入估算采用包含 schema 与消息开销的 UTF-8 字节数，输出预留整个 `MAX_OUTPUT_TOKENS`。这个策略较保守，可能提前拒绝本来可以执行的请求；它不是供应商 tokenizer 或实时账单硬封顶。缺少 usage、HTTP 错误和超时时仍保留该次预算预留；完整计量不可得时聚合 Token 与计量费用为 `null`。逐次已知计量仍保留在 `usage.calls`，预算占用单列为 `budget_estimated_usd`。计量费用使用配置单价计算，包含无效响应的用量。

只对结构化格式/契约错误、连接错误、429 和 5xx 使用共享的一次重试。输出截断、超时、预算耗尽、身份或请求错误均停止后续调用。守护线程在截止后返回控制权，底层正在进行的 HTTP 请求可能持续到 SDK 超时；已发出的请求仍可能收费，程序不会因此再试或继续后续节点。

## 契约与边界

真实模型通过系统规则与 JSON schema 接收输出要求，返回后使用 Pydantic 校验。额外检查包括事实字段引用、对同伴立场的逐字引用、投入时间上限、方案包含全部用户约束，以及有时间分歧或未解决异议时必须保留分歧字段。格式问题可消耗一次修复机会，原始错误响应不会加入新 prompt 或诊断日志。

这些结构检查支持审阅，但不能完全判定自然语言是否忠实、是否合理满足所有约束。用户仍需检查证据、立场变化和最终计划。LangSmith tracing 默认关闭；结果只记录安全的错误类别，API 原始错误内容与凭证不写入报告。

契约失败时，`usage.calls[].validation_errors` 记录固定错误码和 schema 字段位置，例如 `unknown_evidence_reference @ evidence_refs`。JSON/schema 错误与业务约束错误分别定位，Markdown 同时显示这些诊断。原始响应、被拒绝的值、自由文本错误消息及未知字段名都不写入诊断；重试只收到这些安全诊断和完整契约。

证据路径相对 `request` 对象，例如 `time_summary.category_minutes.sleep`，从每次输入生成的可选路径列表中选择。`request.` 前缀、数组下标或带解释的路径均不符合契约，程序会提示修复而非静默接受。
